# Linux recovered-app runtime dependencies

## Verified result and boundary

On 2026-10-18, all **39 runtime distributions** were resolved from official
PyPI, downloaded as wheels, verified against registry SHA-256 hashes, and
installed from a local wheelhouse with `--no-index --require-hashes` into:

```text
/tmp/cachecad-app-runtime-env/bin/python
```

`pip check` reports `No broken requirements found.` A standalone, newly written
Qt smoke passed with PySide6 **6.9.2**, Qt **6.9.2**, the `offscreen` platform
plugin, a rendered 320 × 64 label, and event-loop exit code 0. That smoke did
not import or run any recovered/maintained application module, resource module,
credential loader, account client, updater, or application telemetry.

This establishes an installed dependency environment and a basic real-Qt
capability. It does not establish that CacheCAD starts, synchronizes correctly,
authenticates, or works on Windows. Application and offline-fixture validation
have their own gates. No vendor executable or Windows DLL was run or copied
into this environment.

## Files and dependency provenance

- `requirements/runtime-linux.in`: direct runtime requirements plus explicit
  observed-version constraints.
- `requirements/runtime-linux.lock`: complete resolved closure, with one exact
  version and one SHA-256-locked wheel per distribution. Comments preserve each
  wheel filename and byte count. It rejects source distributions.
- These are independent of `requirements/linux-build.lock` and the
  maintenance-tool package. Neither build tools nor their dependencies were
  added to the application runtime.

The static import audit in `../prototype/dependency-inventory.json` and the
recovered/maintained source identifies PySide6, Requests, httplib2,
google-api-python-client, google-auth, google-auth-oauthlib,
google-cloud-logging, Send2Trash, and tzlocal as application requirements.
Standard-library imports do not become PyPI dependencies. The application uses
QtCore, QtGui, QtWidgets, and QtNetwork; this first runtime intentionally retains
the full official PySide6 distribution, including Addons and Essentials.

Three required direct dependencies had no established original version. The

The runtime lock covers declared dependencies for the selected Linux/Python
target, not every optional extra. In particular, platform-conditioned Windows
packages are excluded. Dependency compatibility and artifact integrity are not
a vulnerability review, a license approval, or a guarantee of compatibility
with the recovered application.

## Reproduce the hash-locked installation

Use an approved CPython 3.12 interpreter on Linux x86_64 with compatible system
libraries. Run from the repository root. The first step needs official-PyPI
network access; the installation step does not. Do not reuse a wheelhouse with
unrelated artifacts or a venv containing other packages.

```sh
python3 -m pip --isolated --disable-pip-version-check --no-input download \
  --no-cache-dir --index-url https://pypi.org/simple \
  --only-binary :all: --require-hashes \
  --platform manylinux_2_28_x86_64 \
  --platform manylinux_2_17_x86_64 \
  --platform manylinux2014_x86_64 \
  --platform manylinux2010_x86_64 \
  --platform manylinux1_x86_64 \
  --python-version 312 --implementation cp \
  --abi cp312 --abi abi3 --abi none \
  --dest /tmp/cachecad-runtime-wheelhouse \
  -r requirements/runtime-linux.lock

python3 -m venv --without-pip /tmp/cachecad-app-runtime-env
python3 -m pip --isolated --disable-pip-version-check --no-input \
  --python /tmp/cachecad-app-runtime-env install \
  --no-index --find-links /tmp/cachecad-runtime-wheelhouse \
  --only-binary :all: --require-hashes \
  -r requirements/runtime-linux.lock

python3 -m pip --isolated --disable-pip-version-check --no-cache-dir \
  --python /tmp/cachecad-app-runtime-env check
```

Do not add `--no-deps`: resolving the full lock at install time also detects
missing declared dependencies. All dependencies in the successful installation
were locally available and hash-checked; no wheel build or arbitrary upstream
build script was required. Keeping the verified wheelhouse is necessary for a
future installation when PyPI is unavailable.

### How the first lock was generated

The candidate resolution used only official PyPI and no repository uv source
overrides:

```sh
uv --no-config --cache-dir /tmp/cachecad-runtime-uv-cache pip compile \
  requirements/runtime-linux.in --python python3.12 \
  --python-platform x86_64-manylinux_2_28 \
  --default-index https://pypi.org/simple --only-binary :all: \
  --prerelease disallow --exclude-newer 2026-10-18T17:14:00Z \
  --generate-hashes --no-annotate \
  -o /tmp/cachecad-runtime-resolved.txt
```

The three previously unverified direct versions were pinned in the input after
this first resolution. The candidate file includes hashes for multiple
platform artifacts. The same download command above was then run with the
candidate file to select the actual target wheels. Each downloaded wheel's
`.dist-info/METADATA` supplied its canonical distribution name and exact
version. Each file's locally calculated SHA-256 was checked against the
candidate hashes. The final lock records only those 39 wheel hashes and
rejects all source distributions. The downloaded set was checked for duplicate
distribution names and for exact equality with the candidate package/version
set before installation.

Use the checked-in final lock to reproduce this environment. A fresh resolution
is an intentional dependency update requiring review; it is not needed to
install or test the existing lock. Changes in registry metadata may prevent
re-deriving an identical candidate resolution even with a date cutoff.

## Standalone real-Qt smoke

The following was run with the installed runtime, a disposable HOME, isolated
Python mode, and no application path added to `sys.path`:

```sh
mkdir -p /tmp/cachecad-qt-smoke-profile/runtime
chmod 700 /tmp/cachecad-qt-smoke-profile/runtime
env -i PATH=/usr/bin:/bin HOME=/tmp/cachecad-qt-smoke-profile \
  XDG_RUNTIME_DIR=/tmp/cachecad-qt-smoke-profile/runtime \
  QT_QPA_PLATFORM=offscreen \
  /tmp/cachecad-app-runtime-env/bin/python -I - <<'PY'
import json
import sys

blocked_events = []
def audit(event, args):
    if event in {'socket.connect', 'socket.connect_ex',
                 'socket.bind', 'socket.getaddrinfo'}:
        blocked_events.append(event)
        raise RuntimeError('Network activity is not allowed in Qt-only smoke')
sys.addaudithook(audit)

import PySide6
from PySide6.QtCore import QTimer, qVersion
from PySide6.QtGui import QImage
from PySide6.QtWidgets import QApplication, QLabel

app = QApplication(['cachecad-qt-only-smoke'])
assert app.platformName() == 'offscreen'
widget = QLabel('CacheCAD Qt runtime smoke')
widget.resize(320, 64)
widget.show()
app.processEvents()
image = QImage(widget.size(), QImage.Format.Format_ARGB32)
image.fill(0)
widget.render(image)
assert not image.isNull()
QTimer.singleShot(0, app.quit)
exit_code = app.exec()
widget.close()
assert exit_code == 0
assert not blocked_events
application_modules = [
    name for name in sys.modules
    if name == 'resources_rc' or name.startswith(('app.', 'core.', 'gui.', 'utils.'))
]
assert not application_modules
print(json.dumps({
    'PySide6': PySide6.__version__, 'Qt': qVersion(),
    'platform_plugin': app.platformName(),
    'render_size': [image.width(), image.height()],
    'event_loop_exit': exit_code,
    'application_modules_imported': application_modules,
    'blocked_network_events': blocked_events,
}, indent=2))
PY
```

The Python audit hook is a defense-in-depth check, not an operating-system
network sandbox and not a monitor of all native-library network activity. This
test's source uses only a local widget, image, and event loop. It does not
authorize or exercise account, cloud, credential, or updater behavior.

## Remaining gates

No dependency-installation or basic offscreen-Qt blocker remained on the
validation host. The only initial tooling error was uv's default cache location
being read-only; using `/tmp/cachecad-runtime-uv-cache` resolved it without
changing host permissions.

The final source/resources, credential-free startup, import-time side effects,
disposable application profile, scanner/service fixtures, and deterministic
application packaging must still be checked by their respective tests. Refer
to the current application QA report for those results. This report must not
be used as evidence for live account operation, lossless sync, Windows or
SolidWorks integration, or installer readiness.

## Hosted Ubuntu shared libraries

The first hosted actual-application test exposed `libEGL.so.1` missing from the
Ubuntu 24.04 runner, before QtWidgets could import. CI now explicitly installs
`libegl1`, `libgl1` and `libopengl0` from official Ubuntu repositories before the
hash-locked Python runtime. These supply the EGL/OpenGL shared-library boundary
that PySide6 wheels do not bundle. The Python hash lock is not a complete pinned
OS image; apt package revisions remain selected by the runner repositories.
See the [Ubuntu libegl1 package](https://packages.ubuntu.com/noble/libegl1).
